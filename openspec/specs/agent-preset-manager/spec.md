# agent-preset-manager Specification

## Purpose
让用户在 DSH 0.2.0 线（preset 只接受运行期注册表声明、不再扫描任何目录）继续使用本地目录里的 agent preset：把本地目录里的预设读出来声明给注册表、让开关状态跨重启保持，并在设置页的「本地插件」入口里以一个 tab 提供新增、编辑、导入、删除与可用性检查。

## Requirements

### Requirement: 本地插件页里的预设 tab

系统 SHALL 在设置页「本地插件」入口的 tab 列表里提供一个名为「Agent 预设」的 tab（稳定 id `agent-presets`，排序值 20），MUST NOT 创建新的设置导航行。该 tab 的内容只有渲染在用户切到它时才产出，且 MUST NOT 要求用户刷新页面才能看到它存在（tab 行随客户端插件装载登记）。对不支持该 tab 槽的宿主（槽位缺失），系统 MUST 静默跳过登记而不是抛错。

#### Scenario: 打开本地插件页看到预设 tab
- **WHEN** 插件已在本 profile 激活，用户打开设置 → 本地插件
- **THEN** tab 栏里出现「Agent 预设」，与「本地插件」等既有 tab 并列；点击后展示预设管理面板

#### Scenario: 不新增设置导航行
- **WHEN** 插件激活后用户查看设置页左侧导航
- **THEN** 导航行与未装插件时完全一致（不出现「Agent 预设」之类的新入口）

#### Scenario: 宿主没有该 tab 槽
- **WHEN** 客户端运行在未声明 `settings.localPlugins.tab` 列表槽的宿主上
- **THEN** 插件不登记 tab、不抛异常，页面其余部分正常工作

### Requirement: 扫描两类预设目录并呈现状态

系统 SHALL 扫描 `$DSH_HOME/.agent-presets/<id>/`（旧目录）与 `$DSH_HOME/agent-presets/<id>/`（新库目录），每个目录读取 `preset.yml`（显示用 `name`、`description`、`order`）与 `agent.cordis.yml`（子插件行清单），并 MUST 为每个发现的 id 呈现一行，含：显示名、描述、来源目录、行数、启用状态之一（`已启用` / `已停用` / `启用失败` / `内容无效` / `位置冲突`）。目录不存在时 MUST 视为空集而非错误；`preset.yml` 缺失或不可解析时 MUST 仍列出该行并以目录名作为显示名、同时标注元数据不可读。

#### Scenario: 两个目录都有内容
- **WHEN** `$DSH_HOME/.agent-presets/liangshen/` 与新库目录 `$DSH_HOME/agent-presets/foo/` 同时存在
- **THEN** 面板列出 liangshen 与 foo 两行，来源目录分别标为旧目录与新库目录

#### Scenario: 目录不存在
- **WHEN** `$DSH_HOME/agent-presets/` 尚不存在
- **THEN** 面板仍正常渲染（只列旧目录里的项），不报错

#### Scenario: 元数据不可读
- **WHEN** 某目录缺少 `preset.yml` 或其 YAML 解析失败
- **THEN** 该行仍然出现，显示名为目录名，并标注「元数据不可读」，其组成仍可查看与启用

#### Scenario: 同一 id 出现在两个目录
- **WHEN** 两个目录下存在同名 id
- **THEN** 只呈现一行并标为 `位置冲突`，明确说明哪个目录是生效来源（旧目录优先），且不自动启用

### Requirement: 启用即向注册表声明，停用即撤销

系统 SHALL 通过宿主 agent preset 注册表的运行期注册接口把某个本地预设声明出去，并把注册表返回的撤销句柄保存下来；停用 SHALL 调用该撤销句柄。声明用的显示名 MUST 取自 `preset.yml`；当 `preset.yml` 缺失且没有可用显示名时 MUST 使用 id 作为显示名（否则面板会显示为空白）。声明 MUST 使用被声明预设自己的目录作为行名解析基点，使组成里的相对行名（如 `./tool-bootstrap.mjs`）指向该预设自己目录下的文件。启用与停用 MUST 立即作用于**新建会话**；运行中的会话 MUST 保持其原有预设不变。

#### Scenario: 启用后新会话可选到它
- **WHEN** 用户在某行打开开关（该预设的组成可解析）
- **THEN** 该行显示 `已启用`；用户新建会话时，预设选择器里出现这个预设（显示名取自 `preset.yml`）

#### Scenario: 停用后新会话不再可选
- **WHEN** 用户关闭某已启用预设的开关
- **THEN** 该行显示 `已停用`，新建会话的预设选择器里不再出现它，磁盘上的目录与文件原样保留

#### Scenario: 相对行名按预设目录解析
- **WHEN** 某预设的组成里含行名 `./tool-bootstrap.mjs`，该文件就在这个预设自己的目录下
- **THEN** 启用后该行被成功装载（而不是在其它目录里寻找该文件）

#### Scenario: 运行中会话不受影响
- **WHEN** 用户在当前会话进行中启用或停用某个预设
- **THEN** 当前会话的预设与工具链不变，改动只对新建会话生效

### Requirement: 启用失败的呈现与恢复

当注册表以「id 重复」「组成无效」「服务需要隔离 realm 却泄漏到全局」等原因拒绝声明、或声明成功但预设激活失败时，系统 MUST 把该行标为 `启用失败`、保留它在面板上的可操作位置、并展示来自宿主的原始错误文本。系统 MUST NOT 因为某个预设失败而中断其它预设的启用或停用，也 MUST NOT 让宿主进程因此崩溃。当宿主的 agent preset 注册表服务不可用时（例如旧线宿主），面板 MUST 呈现全部预设为只读列表并给出明确提示，一切写操作 MUST 被拒绝且不产生磁盘副作用。

#### Scenario: id 与已声明预设撞车
- **WHEN** 某预设的 id 与已声明预设（例如内置的 `standard` 或另一个已启用的本地预设）重复
- **THEN** 该行显示 `启用失败` 与宿主给出的重复错误文本，其他预设的开关仍可正常操作

#### Scenario: 组成内容无效
- **WHEN** 某预设的 `agent.cordis.yml` 解析失败，或解析出的行缺少非空 `name`
- **THEN** 该行显示 `内容无效` 与具体原因（哪一行、缺什么），不调用注册表，且不写任何文件

#### Scenario: 服务泄漏到全局 realm
- **WHEN** 某个预设里的行提供 Cordis 服务但没有放在带 isolate 的分组行里，声明被宿主以「服务需要 isolate realm」拒绝
- **THEN** 该行显示 `启用失败` 并原样展示该错误，用户能据此定位需要加分组的那一行

#### Scenario: 注册表服务缺失
- **WHEN** 宿主未提供 agent preset 注册表服务
- **THEN** 面板列出全部本地预设但所有开关禁用，并显示「当前 DSH 版本不支持运行期声明 preset」之类的提示；任何写操作都被拒绝

### Requirement: 启用集合跨重启保持

系统 SHALL 把「哪些 id 处于启用」持久化到 `$DSH_HOME/agent-preset-manager/state.json`，并在插件启动时重放这些声明，使重启后无需用户操作即恢复原状。首启（状态文件不存在）MUST 视为没有任何 id 被启用，MUST NOT 自动启用磁盘上发现的任何预设。状态文件的读取失败 MUST 降级为空集并继续启动；状态里记录的、磁盘上已不存在的 id MUST 被忽略（不报错、不阻断其它 id 的恢复）。

#### Scenario: 重启后自动恢复
- **WHEN** 用户启用某预设，随后重启 DSH
- **THEN** 该预设重新出现为 `已启用`，新建会话可直接选到它，用户无需再点一次开关

#### Scenario: 首次安装不自动启用
- **WHEN** 用户第一次安装本插件（state.json 不存在），磁盘上已有若干本地预设
- **THEN** 所有行显示 `已停用`，没有任何本地预设被声明给注册表

#### Scenario: 状态文件损坏
- **WHEN** `state.json` 内容不是合法 JSON
- **THEN** 插件以「无启用项」继续启动（面板可正常打开并操作），并在面板上提示状态文件不可读

#### Scenario: 状态里有已消失的 id
- **WHEN** `state.json` 记录了 id `foo`，但两个预设目录下都不再有 `foo`
- **THEN** 启动时不尝试声明 `foo`、不报错；用户重新放回该目录后，启用状态按记录恢复

### Requirement: 新增预设

系统 SHALL 支持在面板内新增一个预设：用户提供 id（MUST 匹配 `^[a-z0-9][a-z0-9_-]{0,63}$`）与显示名，系统以 0.2.0 内置 `standard` 预设的子插件清单作为初始组成骨架，把它落成新库目录下的 `<id>/preset.yml` 与 `<id>/agent.cordis.yml`。id MUST NOT 与两个目录下已有的 id、以及已被声明的预设 id 重复；撞车时 MUST 拒绝并指出与哪个来源冲突。骨架来源不可读时 MUST 拒绝创建并明确报错，MUST NOT 留下只有一半的目录。

#### Scenario: 新增成功且组成可用
- **WHEN** 用户填入合法且不重复的 id 与显示名并确认新增
- **THEN** 新库目录下生成 `<id>/preset.yml` 与 `<id>/agent.cordis.yml`，面板出现该行（`已停用`），其组成等于内置 standard 的子插件清单

#### Scenario: id 非法
- **WHEN** 用户填入的 id 含大写字母、空格、路径分隔符或超出长度限制
- **THEN** 拒绝创建并说明允许的字符规则，磁盘不产生任何目录

#### Scenario: id 撞车
- **WHEN** 用户填入的 id 与已有目录名或已声明预设 id 相同
- **THEN** 拒绝创建并指出冲突来源，已有的目录与声明不被改动

#### Scenario: 骨架来源不可读
- **WHEN** 内置 `standard` 组成文件不存在或无法解析
- **THEN** 拒绝创建并明确报错，不留下半成品目录

### Requirement: 编辑组成并保留备份

系统 SHALL 允许在面板内编辑某个预设的 `agent.cordis.yml` 与显示名/描述，保存前 MUST 把被覆盖的文件备份到该预设目录下的 `.backup/`，并 MUST 只保留该文件最近 3 份备份（更旧的自动清理）。保存 MUST 以原子替换方式写入（不产生被截断的半个文件）。备份写入失败时 MUST 拒绝保存并报错。保存本身 MUST NOT 改变该预设的启用状态：已启用的预设保存后 MUST 仍处于启用（组成按新内容重新装载）。

#### Scenario: 保存后生成备份
- **WHEN** 用户编辑并保存某预设的组成
- **THEN** 新内容写入 `agent.cordis.yml`，旧内容留在 `<id>/.backup/` 下的一个带时间戳文件里

#### Scenario: 备份不超过 3 份
- **WHEN** 同一文件被连续保存 4 次以上
- **THEN** `.backup/` 里最多保留最近 3 份，更旧的被清理

#### Scenario: 保存不改变启用状态
- **WHEN** 用户对一个 `已启用` 的预设保存新的组成
- **THEN** 该行仍显示 `已启用`，新建会话使用新组成

#### Scenario: 备份失败则不落盘
- **WHEN** 备份目录不可写（权限或磁盘错误）
- **THEN** 保存被拒绝并报错，`agent.cordis.yml` 保持原内容不变

### Requirement: 停用与删除的语义区分

系统 SHALL 提供两个语义不同的破坏性操作：`停用` 只撤销声明、磁盘内容完全保留；`删除` 撤销声明并删除该预设目录。删除 MUST 要求二次确认，确认文案 MUST 指明将被删除的目录路径。删除同时 MUST 清理该 id 在状态文件里的记录。删除一个处于启用状态的预设时，撤销声明 MUST 先于删除目录发生，且删除失败时 MUST 报告「声明已撤销、目录未删除」的实际结果而不是笼统报错。

#### Scenario: 停用不动磁盘
- **WHEN** 用户对某预设执行停用
- **THEN** 该行变为 `已停用`，`preset.yml`、`agent.cordis.yml` 及其它文件一个字节都没变

#### Scenario: 删除需要确认
- **WHEN** 用户点击删除
- **THEN** 出现确认框并展示将被删除的绝对路径；用户取消时不发生任何改动

#### Scenario: 删除启用中的预设
- **WHEN** 用户确认删除一个 `已启用` 的预设
- **THEN** 该预设先被撤销声明（新会话不再出现），随后目录被删除，状态记录被清理，面板上该行消失

#### Scenario: 删除过程中目录删除失败
- **WHEN** 撤销声明成功但目录删除失败（文件被占用等）
- **THEN** 面板报告「已停用，但目录未能删除」并给出原因，该行仍以 `已停用` 存在，供用户重试

### Requirement: 行名可用性检查

系统 SHALL 为某个预设的组成逐行判定可用性，并将每行标为 `可用`、`存疑` 或 `不可用` 之一，同时给出具名理由。判定规则：`@deepseek-ai/dsh-*` 这类内置包按运行时实际提供的包（含子路径）判定；`cordis:` 前缀按宿主内置行判定；以 `./` 或绝对路径给出的行名按该预设目录下的文件是否存在判定；带 `config.plugins` 的分组行递归判定其子行。检查结果 MUST 只影响面板呈现，MUST NOT 阻止用户启用该预设。对判定为 `不可用` 的行，面板 MUST 指出行 id 与行名原文，使用户能定位到要改的是哪一行。

#### Scenario: 包已从发行物移除
- **WHEN** 组成里含 `name: '@deepseek-ai/dsh-workflow-worker-thread'`，而运行时已不提供该包
- **THEN** 该行标为 `不可用`，理由说明运行时找不到该包；同一预设里的其它行不受影响

#### Scenario: 相对文件缺失
- **WHEN** 组成里含 `name: ./custom-bash.mjs` 但该文件不在这个预设目录下
- **THEN** 该行标为 `不可用`，理由说明该文件不存在

#### Scenario: 组行递归
- **WHEN** 组成里某个 `cordis:group` 行内部含一个不可用的子行
- **THEN** 面板标出该子行（含它在组内的位置），组行本身仍可被识别

#### Scenario: 检查不阻止启用
- **WHEN** 某预设含 1 行不可用、其余行可用，用户仍打开开关
- **THEN** 系统照常尝试声明该预设并如实呈现注册表的结果，不因检查结论而拒绝操作

### Requirement: 从外部目录导入

系统 SHALL 支持把任意绝对路径下的预设目录复制进新库目录：输入绝对路径后，系统 MUST 先校验源目录含 `preset.yml` 或 `agent.cordis.yml`、从目录名取得 id、id 合法且不与现有 id 撞车，并把「将导入的 id、显示名、行数」显示给用户确认后才复制。源目录必须是目录本身而不是其父目录。目标已存在时 MUST 拒绝并要求用户先删除或改名，MUST NOT 静默覆盖。复制失败时 MUST 清理本次已创建的部分并报告失败。

#### Scenario: 导入成功
- **WHEN** 用户填入一个合法的外部预设目录绝对路径并确认导入
- **THEN** 该目录内容被复制到 `$DSH_HOME/agent-presets/<id>/`，面板出现该行（`已停用`），原始目录保持不动

#### Scenario: 路径不是预设目录
- **WHEN** 用户填入的路径不存在、不是目录、或既没有 `preset.yml` 也没有 `agent.cordis.yml`
- **THEN** 拒绝导入并说明原因，不做任何复制

#### Scenario: 目标 id 已存在
- **WHEN** 目标库目录下已存在同名 id
- **THEN** 拒绝导入并提示先删除或改名，已有目录不被覆盖

### Requirement: 旧目录的迁移助手

系统 SHALL 为旧目录（`$DSH_HOME/.agent-presets/<id>/`）里的预设提供迁移能力：把它复制为新格式的新库目录条目，迁移后 MUST 明确告知用户旧目录仍然存在、可以自行确认后再删除。迁移 MUST NOT 自动删除旧目录，也 MUST NOT 自动修复组成内容。迁移前 MUST 先告知该组成里的不可用行（若有），让用户在迁移前决定是否继续。

#### Scenario: 迁移旧预设
- **WHEN** 用户对旧目录里的 `liangshen` 执行迁移
- **THEN** 新库目录下出现内容等效的 `liangshen/`，旧目录原样保留，面板同时把新条目列为 `已停用`

#### Scenario: 迁移前提示不可用行
- **WHEN** 被迁移的组成里存在判定为 `不可用` 的行
- **THEN** 迁移确认过程列出这些行（行 id 与原行名），用户可以选择继续或取消

#### Scenario: 不覆盖已有新条目
- **WHEN** 新库目录下已存在同名 id
- **THEN** 拒绝迁移并提示，已有条目不被改动

### Requirement: 不干扰既有 setup

系统 MUST NOT 修改 profile 的激活清单、`dsh.profile.bundles`、profile 依赖或其它插件的行；这些安装动作由本仓既有机制（本地插件管理器）承担。系统 MUST NOT 触碰服务器上另一个已安装的第三方预设中心插件的库目录约定与凭证文件（如 provenance 文件），两者对同名 id 的冲突由运行时注册表的重复判定如实呈现。

#### Scenario: 面板操作不写 profile
- **WHEN** 用户在本面板执行启用、停用、新增、编辑、删除、导入、迁移中的任意操作
- **THEN** profile 的 `cordis.patch.yml` 与 `package.json` 保持字节不变

#### Scenario: 与第三方预设中心共存
- **WHEN** 本机已安装另一个使用 `$DSH_HOME/agent-presets/` 作为库目录的第三方插件且其中已有条目
- **THEN** 本插件能列出这些条目、不删除其凭证文件，若用户在两边对同一 id 都做启用则如实显示注册表的重复错误
